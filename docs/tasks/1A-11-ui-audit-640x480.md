# 1A-11 — 640x480 UI screenshot audit

- **Status:** Todo
- **Difficulty:** medium
- **Depends on:** 1A-01
- **Context budget:** ~50k tokens

## Goal
Automatically capture a 640x480 screenshot of every screen a handheld player sees, so that Opus can list layout
problems (overflow, clipped text, unreadable sizes) and create fix cards `1A-2x`.

Screens: main menu; Singleplayer map selection; player/CO/AI selection; game rules; Options (each tab); in-game
map; unit action menu; in-game menu (Escape); FieldInfo (key I); CO info; victory screen; load-game dialog;
loading screen.

## Steps
1. Add `tools/handheld/ui-audit/init.js`, an automation script in the style of `tools/handheld/ramtest/init.js`
   and of `_test/init.js` (repo root; it already shows how to open many menus, e.g. `showCOInfo`,
   `showGameInfo`, `showXmlFileDialog`, `victoryInfo`).
2. Add `tools/handheld/ui-audit.sh`. It runs the game in Docker/Xvfb at 640x480 like `measure-ram.sh`. Each
   step of the script prints `UIAUDIT: <name>`, and the shell captures `xwd` → PNG after each marker. Simplest
   way: the JS waits for a fixed delay between steps through a timer, or the shell polls the log for markers.
3. Write the PNGs to `.handheld/receipts/1A-11-ui/<nn>-<name>.png` plus `index.txt`.
4. Do not judge the screenshots yourself. Opus reviews them (Jev cannot see images).

## Acceptance criteria
1. At least 12 of the listed screens are captured as non-black PNGs at 640x480. `index.txt` lists them.
2. No game source file is modified.
3. The card's Result lists which screens could not be reached automatically, and why.
